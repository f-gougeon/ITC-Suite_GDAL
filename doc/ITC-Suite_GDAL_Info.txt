Introduction:

	For more details on how to run the ITC-Suite, please check the ITC-Suite Manual from 2010:

	Gougeon, F.A. 2010. The ITC Suite Manual : A Semi-Automatic Individual Tree Crown (ITC) Approach 
	to Forest Inventories. Natural Resources Canada, Canadian Forest Service, Pacific Forestry Centre,
 	Victoria, B.C. Canada. June 2010. 92  p. 
	http://cfs.nrcan.gc.ca/publications/?id=31918

	The ITC-Suite, first developed for the ARIES image analysis system in the 90's,
	mostly ran under PCI/XPACE, then PCI/EASI, with PCI/ImageWorks and later PCI/Geomatica 
	to display and deal with PCI's ".pix" files (PCI v2010-2022 at this time)

	Instead of a PCI file containning all, it is now assumed that all will be in 
	a single "project directory": images as tif files, bitmap as 1-bit tif files, 
	vector layers as shp files, signatures as discrete files, etc., and
	that ArcGIS (or other software) may be used to view all these.

	In order to deal with less items on the command line, file nomenclature is
	often predefined, but often using a "base file name" from the main image file.

	Having an image file name such as "BaseName_IRGB.tif" for example
	will ensure that other files will be of the type "BaseName_aaaa.ext"
	For examples, "BaseName_VFOL.tif"   as output from itcvfol_g.exe
	or "BaseName_ISOL.tif"  as output from itcisol_g.exe
	Of course the "BaseName" should reflects the name of the main project in that directory.
	The underscore is use to separate the "base file name" from the rest of the file name.
	Full directory path is now mostly supported (i.e., not fully tested yet as the philosophy 
	was to do everything in the same directory from a "cmd windows"). However, it was needed
	for the integration of the GDAL version of the Suite used with a ArcGIS Toolbox (GUI).

	The GDAL version of the ITC-Suite can be used from ArcGIS or ArcGISPro via appropriate
	toolboxes, allowing users to stay completely with that environment.


	NOTE:	Partial use of a PCI file is often possible (as input). However,
		user entered segment numbers will be that of GDAL, not of PCI.
		Use "gdalinfo" and "ogrinfo" on the PCI file to find that order.
		(e.g., bitmaps are numbered after images, vector layers are separate,
		signature segments are not visible, ...)

	NOTE:   The "ITC-Suite Manual" and "ITC-Suite.chm" are still very relevant to all this 
		but should be used as guides, not gospel.

	NOTE:	My GDAL programs always complain when overwriting an exiting output file.
		Most of the time, it is not an issue. However, sometimes when ArcGIS has control 
		of the file, it may not overwrite at all and leave you with previous results

This document describe the "GDAL ITC-Suite programs" and their parameters as used
from a "cmd window" (under the Windows operating system) or from a "terminal window"
under a Linux operating system.

However, they can be used from a convenient GUI under ArcGIS (from a ToolBox).
Here, we will give the examples for ArcGISPro and GDAL v3.10

The "ITC-Suite-GDAL-v3-10.tbx" toolbox shows a list of the "main" ITC-Suite programs.
Clicking any of them will allow you to enter its parameters and run the program.

*Before running* a program, one needs to run a script (once) that will setup the
environment for the GDAL ITC-Suite and for GDAL, for example:  "GDAL_Setup_V3_10"
that should be in that toolbox.

This will call a Python program (GDAL_V3_10_Setup.py) that will do the setups.
You may need to modify that program (within Arc or as a text file) if the locations
of the GDAL ITC-Suite or GDAL itself (and geo projections) are different on your PC.


N.B.: Some utility programs (below) are not listed in the ArcGIS toolbox.

	Program name: 	itcmg_g.cpp (for GDAL)

	Author: 	François A. Gougeon
	Date:		March-July 2020 (COVID-19 version)

C+
C	ITCMG.cpp    (ITC Mask Generator)
c
c 	ITC Mask Generator - Generates LIT/SHADED/TT masks
C
C	This is a program for the PCI EASI/PACE Image Analysis System that takes the
C	bitmap generated by ITCISOL and the same illumination channel to generate a bitmap
C	assumed representative of the lit side, shaded side, or top of tree crowns (i.e., MAX).  
c	This bitmap may be used as "extra bitmap" mask (EXTBIT) in ITCSSG and ITCSC
c	to create signatures and classify trees using only that "purer" part of the crown.
c
c	Optionally (for research purposes), the bitmap of automatically delineated 
c	crowns (ISOLBIT) can be replaced by a vector layer of manually delineated crowns.
C
c**************************
c
c	PROGRAM USAGE EXAMPLE
c
c	Using PCI Variable Notation:
c
c	> itcmg_g   ILLUMCH  ISOLBIT  MASKTYPE
c
c
c	> itcmg_g SECTEUR_CH5.tif SECTEUR_ISOL.tif LIT	(most typical)
c
c	Program will create "SECTEUR_MG.tif" that you can rename later
c
c	IF some input files are PCI files OR other multi-feature files
c	an additional question will be asked about channel or bitmap 
c	number to use (in GDAL, bitmap numbers are sequential # after last 
c	channel number, if 5 channel, first bitmap is Ch6; and vector layers
c	are independent, starting at 1)
c	Please use "gdalinfo" and "ogrinfo" on files to find out numbering scheme)
c
c	Usage with manual trees and other notations:
c
c	> itcmg_g SECTEUR_CH5.tif SECTEUR_VEC2.shp LIT

c	> itcmg_g SECTEUR.pix,5 SECTEUR_VEC2.shp LIT

c	> itcmg_g SECTEUR.pix SECTEUR.pix LIT	
	NOTE: 2nd file will ask which bitmap or vector layer to use
c
c	> itcmg_g SECTEUR.pix,5 SECTEUR.pix,2 LIT	
	NOTE:	Will use CH5 and segment 2 (bitmap or vector, here vector)
C-

#### GDAL PROGRAM USAGE:

> itcssg_g FILE DBIC ISOLBIT EXTBIT TRAINSEG SIGTYPE { BITBOUND TREETYPE SDBOUT} {CLASSCODE (for slayer mode) }

> itcssg_g Secteur.pix 1,-4 7 8 10,-12 MEAN AUTO ITC 2.5

*** NOTE*** In the case of PCI file, layer# are Gdal layer number (as per ogrinfo)  not PCI#


With TIF files:

> itcssg_g SECTEUR_IRGB.tif 1,-4 SECTEUR_ISOL.tif SECTEUR_MG.tif 2 MEAN AUTO ITC 3
	where training areas 2 could be secteur_VEC2.shp  OR secteur_BM2.tif (it will try both)
	However, it could lead to confusion unless always using one type (shp) or the other
	as numbers (e.g., 2) may overlap

Similarly:

> itcssg_g SECTEUR_IRGB.tif 1,-4 SECTEUR_ISOL.tif SECTEUR_MG.tif 2,-7 MEAN AUTO ITC 3


Other mode:

> itcssg_g SECTEUR_IRGB.tif 1,-4 SECTEUR_ISOL.tif SECTEUR_MG.tif secteur_VEC.shp,2,-7 MEAN AUTO ITC 3

	secteur_VEC2.shp, secteur_VEC3.shp, secteur_VEC4.shp, ... to VEC7 will be used  

Alternative notation:

> itcssg_g SECTEUR_IRGB.tif 1,-4 SECTEUR_ISOL.tif SECTEUR_MG.tif secteur_VEC.shp,2,3,5,6 MEAN AUTO ITC 3

#### GDAL PROGRAM USAGE:

In order to deal with simple numbers on command line, file nomenclature 
is often predefined, but always using base file name, here "SECTEUR"

>  itcsc_g FILE DBIC ISOLBIT EXTBIT SigSEG SIGTYPE TREETYPE

>  itcsc_g SECTEUR.pix 1,-3 10 11 10,-12 MEAN ITC

	Will pickup all info from the PCI file, but with GDAL channel ordering


>  itcsc_g SECTEUR.tif 1,-3 10 11 12,-14 MEAN ITC

>  itcsc_g SECTEUR.tif 1,-3 10 11 12,-14 MEAN ITC

		Image channels 1,2,3 are in a tif file
		
		As per user input, ISOLBIT number to use: 10
		ISOLBIT file_in  :  SECTEUR_BM10.tif

		As per user, EXTBIT  number to use: 11
		EXTMASK file_in  :  SECTEUR_BM11.tif
		
		Signature file_in  :  SECTEUR_SIG_BM12.sig 
		Signature file_in  :  SECTEUR_SIG_BM13.sig		
		Signature file_in  :  SECTEUR_SIG_BM14.sig	
		
	meaning that signature were generated by "itcssg_g" from training area bitmaps 12,13,14	

	**NOTE: Program will also look for SECTEUR_SIG_VEC2.sig (when from polygon training areas)
		Presently, SECTEUR_SIG_BM12.sig as priority over SECTEUR_SIG_VEC12.sig 
		

	
You can also direct the search for signature files by giving a base file name :


>  itcsc_g SECTEUR_IRGB.tif 1,-4 SECTEUR_ISOL.tif SECTEUR_MG.tif Secteur_SIG_VEC.sig,2,3 MEAN ITC



		
### The output from the classifier will be bitmaps (1-bit tifs) named:

	SECTEUR_Class1.tif, SECTEUR_Class2.tif, SECTEUR_Class3.tif, ...
	
		
To classify manual "individual tree polygons" all in a single vector layer in a PCI or a shp file

>  itcsc_g SECTEUR.tif 1,-3 2 18 12,-14 MEAN SLAYER		// single layer is segm 2, LIT is BM 18

>  itcsc_g SECTEUR.tif 1,-3 21 - 12,-14 MEAN SLAYER		// single layer SECTEUR_VEC21.shp, signature=12-14 noLIT

C	ITCCA.cpp		Individual Tree Crown (ITC) Classification Accuracy
C
C	ITCCA determines the classification accuracy of an Individual Tree Crown
C	Classification Process.  A confusion matrix is generated, based on the testing
C	bitmaps that the user specifies and the bitmaps produced from ITCSC as a result of
C	the classification.  The result is a table (matrix) showing both counts of trees
C	and percentages, plus the average accuracy and the overall accuracy.  As well, the
C	counts for unclassified trees is included (percentages and accuracy reflect the
C	presence of the unclassified trees).  The Kappa Coefficient and Kappa Variance
C	is calculated (not including the unclassified trees in the classifications), and 
C	the average crown area of the correctly classified tree crowns is displayed.
C
C
c
c	PROGRAM USAGE
c
c
c	> itcca_g BaseFilename ISOLBIT TESTSEG  CLASSBIT BITBOUND

	where "basefilename" is typically the main tif file contaninng the image (but not used)
	Here, it is just used to create the proper prefix for ISOLBIT, TESTSEG and CLASSBIT files
	ISOLBIT is a bitmap of ITC delineated tree crowns, typically called BFname_ITC.tif
	TESTSEG  can be bitmap or vector layer test areas (or a combination) 
	(e.g., BFname_BM13.tif BFname_VEC2.shp)
	CLASSBIT files are bitmaps resulting from an ITC classification with ITCCA_G
	BITBOUND is as per PCI definition above. POINTS mode is not implemented yet.above

		Will use SECTEUR_BM10.tif to BM12 *OR* VEC10 to Vec12 as testing areas

Program name: 	lattops_g.cpp

Author: 	François A. Gougeon
Date:		July 2023, Nov. 2023

Description:

	Find treetops in dense areas and treetops with specific shadows in
	more open areas, as designated by the directionality mask (DIRMASK).
c
C	This program moves a window of a given size on an input image and
C	detects the local centered grey-level maximum of each window's instance.
C	For the areas covered by an input mask (DIRMASK) (e.g.: directionality
C	mask), it keeps only those max. with a significant low grey level area 
C	(i.e., a shadow) in the direction commensurate with SUNANG (180o + SUNANG).
c	(N.B.: The angle assumes North at top of the image)
c
c	Optionally: Operation under the directionality mask (open areas)
c		    are done on a smoothed version of the image, if supplied
c		    (i.e., if ILLUMCH = a,b). This may improve results.
c	This could also be a completely different channel if more useful for shadows
C
c	Optionally: If DIRMASK = 1, trees from the whole image (except under NFMASK)
c		    are considered to have discrete shadows (was SHADOW_TT) ????
C
c	Org. for full path and ArcGIS compatibility and output : basefilename_TTs.tif
c
c	*** NOTE *** Changed parameters order compared to PCI version (i.e., NFMASK before DIRMASK)
c
c	*** NOTE *** I Will not migrate TREETOPS to GDAL as LATTOPS can do it all
c			
c			
c	- NOTE:	This program (and other of my GDAL progs) always complain when overwriting an exiting 
c		output file. Most of the time it is not an issue. However, sometimes when ArcGIS has
c		control of the file, it may not overwrite at all and leave you with previous results

#### GDAL PROGRAM USAGE

> lattops_g FILE,ILLUMCH NFMASK DIRMASK WINDSIZ THRSHADE SUNANG FORTYPE TTBITM



#### GDAL PROGRAM EXAMPLES

> lattops_g PRF_4x4km.tif,4 - - - 50 - -

Here, the regular TREETOPS will be used throughout the image (CH4 ) using 
a 3x3 window and a shade threshold of 50.


> lattops_g PRF_4x4km.pix,4 PRF_NonFor.tif - - 50 - -

Here, the regular TREETOPS will be used throughout the image (CH4 ) using 
a 3x3 window and a shade threshold of 50. The non-forest areas (PRF_NonFor.tif)
will not be touched.


> lattops_g PRF_4x4km.pix,4 PRF_Forest.tif,-1 - - 50 - -

Here, the regular TREETOPS will be used on CH4 under a FOREST MASK (PRF_Forest.tif) 
(because of the "-1") using a 3x3 window and a shade threshold of 50.



> lattops_g PP1493386_GDAL_Tests.tif 4 386_GDAL_BM9.tif - 5 50 - Mature 

The fouth channel of PP1493386_GDAL_Tests.tif (or .pix) is used
There is no directionality mask, thus regular TREETOP will be used throughout the image
except, under the NFMASK (386_GDAL_BM9.tif)
A 5x5 window will be used, with a shade threshold of 50.

> lattops_g PP1493386_GDAL_Tests.pix,4 BM9.tif BM10.tif 5 50 160 MAT 

The fouth channel of PP1493386_GDAL_Tests.tif (or .pix) is used
Directionality mask is BM10.tif, thus SHADOW_TT will be used throughout the image
under BM10, with a sun azimuth of 160 degrees, except, under the NFMASK (BM9.tif) 
A 5x5 window will be used, with a shade threshold (THRSHADE) of 50.
By default, shadow threshold (cause unsepcified) will be 1.3 * THRSHADE 
It could have been specified as 65, as THRSHADE=50,65 for example.



> lattops_g PP1493386_GDAL_Tests.tif,4,7 BM9.tif BM10.tif 5 50,60 160 MAT Test_TTs.tif
> lattops_g PP1493386_GDAL_Tests.tif 4,7 BM9.tif BM10.tif 5 50,60 160 MAT Test_TTs.tif

Here, a different channel (CH7) is used by the directionality analysis
and a shadow thres of 60 will be used, and an output bitmap file name is given.

	-At this point in time, the program does not deal with :
		multiple channels in one single run (use successive runs)
		multiple correction curves (softwoods & hardwoods)(use successive runs)
		multiple flight lines within a mosaic
		
	Similar to original program for PCI, the program operates on North-South images
	while most flight lines are acquired East-West, so images need to be rotated

	The original program went North-South to access the image "line-by-line"
	to minimize memory usage and work on huge images, huge mosaic.

	Now that the full image is loaded into memory, it's easy to do the rotation
	on the fly. Use the ROT parameter

	Remember, NADCEN="NO is for images that are slighly diagonal in their files

	CWD_SFIL_g.cpp	(Coarse Woody Debris Size Filter (with GDAL))
	
	A mod of ITCSFIL to pickup logs in a field (i.e., cut area) 
	littered by coarse woody debris and stumps.

	From a bitmap showing logs and other coarse woody debris (CWDBM)
	(typically from using a threshold on a normalized blue band)
	this program generates a bitmap containing only the logs
	within a certain range of diameters (using lower and upper
